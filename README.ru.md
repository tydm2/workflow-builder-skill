**Превратите одну идею предметной области в готовый к запуску multi-agent workflow — 1 мозг-оркестратор + N специализированных subagent'ов + триггеры одной строкой.**

`workflow-builder` — это скилл агента, который на основе одного требования к предметной области собирает файловый multi-agent конвейер: мозг-планировщик, экспертные subagent'ы, отдельные knowledge base для каждого агента, явные handoff-контракты и security gate — так что любой агент-хост может загрузить результат и сразу начать работу.

## Чем он выделяется

Большинство шаблонов multi-agent ограничиваются фразой «вот роль и вот промпт». Этот скилл идёт дальше благодаря пяти отличиям:

- **🔒 Security gate (главная особенность)** — автономный шлюз доставки, который проверяет каждый сгенерированный `AGENT.md` и файл базы знаний на prompt injection, вредоносные инструкции, эксфильтрацию данных, отравление цепочки поставок и безопасность платформы, *плюс независимая вторая проверка*. Шаблоны сообщества редко проверяют то, что сами генерируют.
- **🧠 Саморазвивающиеся subagent'ы** — каждый subagent поставляется с **протоколом самоитерации** (feedback-log + usage-log + ретроспективы «5 почему» + contract freeze), поэтому сгенерированный агент продолжает улучшаться на основе реального использования, а не остаётся застывшим промптом.
- **👥 Агенты экспертного уровня — на ваш выбор** — каждый специалист представляет собой либо **панель экспертов** (1 ведущий + 2–4 старших роли с механизмом согласования), либо **одного старшего эксперта**; выбор основан на доказательствах (статьи / репозитории с высоким рейтингом / консенсус сообщества), а решаете *вы* — никаких значений по умолчанию.
- **🔌 Адаптивность к платформам** — выдаёт `AGENT.md` (DSH), `AGENTS.md` (Codex CLI) или `.claude/agents/<name>.md` (Claude Code) с привязкой инструментов под каждую платформу, так что один дизайн работает на разных хостах.
- **♻️ Переиспользование blueprint'ов + ADR** — готовые workflow архивируются как переиспользуемые blueprint'ы с записями Architecture Decision Records, а сам workflow саморазвивается на основе обратной связи от использования.

Плюс: опциональное **исследование скиллов сообщества** (извлечение лучших в своём классе community skills с сохранением источников), **двойной режим «создание + редактирование»** и **единый источник истины** (single source of truth) для файловых контрактов.

## Как это работает — 8 шагов

1. **Уточнение** — вопросы с вариантами ответов о предметной области, режиме использования (new / edit / both), этапах, красных линиях качества, актуальности знаний, community research, триггерных словах и целевой платформе.
2. **Community research (опционально)** — найдите лучшие community skills, выделите переиспользуемые части, сохраните источники, запустите проверку безопасности.
3. **Проектирование топологии** — 1 мозг + 2–4 специалиста; вы выбираете между панелью и одним старшим экспертом; по каждому специалисту — решение о создании/редактировании.
4. **Сборка каркаса** — генерация `agents/<name>/AGENT.md` + `knowledge/` из шаблона устава (таблица переменных заполняется для каждого агента).
5. **Наполнение knowledge base** — встроенные (offline) и обновляемые (сначала поиск, с разделом «свежие обновления»).
6. **Соединение конвейера** — handoff-контракты, диаграмма конвейера в README, реестр триггерных слов, логи уровня workflow, архив blueprint'ов.
7. **Приёмка и доставка** — сквозной разбор «на бумаге», **затем первый end-to-end smoke-прогон**; отчёт о дереве файлов, триггерах и командах первого запуска.
8. **Security gate** — полная проверка каждого устава и файла знаний по пяти пунктам безопасности, плюс независимый второй проход.

## Output

```
your-workflow/
  README.md                  # диаграмма конвейера + реестр триггеров + ADR + протокол итерации во время выполнения
  shared/                    # общие библиотеки между агентами
  agents/<name>/AGENT.md     # устав: идентичность, протокол, красные линии качества, самоитерация
  agents/<name>/knowledge/   # встроенные и обновляемые knowledge base
  blueprints/<domain>.md     # переиспользуемая топология + записи решений ADR
  feedback-log.md / usage-log.md  # саморазвитие на уровне workflow
  <stage>/                   # версионированные артефакты по этапам
```

## Install

```
~/.dsh/skills/workflow-builder/    # глобально
.dsh/skills/workflow-builder/      # на проект
```

Затем вызывайте его фразами вроде *"build me a <domain> workflow"*, *"set up a plan→execute pipeline"*, *"assemble a subagent team"* — или через пункт ④ меню `/skill` в **set-skill**.

## Примеры

- `references/example-novel-mode.md` — конвейер из трёх агентов для написания романа (Planner → Outliner → Writer).
- `examples/deep-research-pipeline/` — самостоятельно собранный конвейер глубокого исследования (Planner → Researcher → Writer → Reviewer) с полными уставами и knowledge base.

## Документация

- `references/pipeline-design.md` — методология топологии, выбор формы экспертов, разделение знаний, community research и проверка безопасности
- `references/agent-charter-template.md` — стандартный шаблон AGENT.md
- `references/prompt-craft.md` — профессиональная спецификация написания промптов для subagent'ов
- `references/platform-adapter.md` — соответствие для DSH / Codex CLI / Claude Code
- `references/contract-spec.md` — единый источник истины (single source of truth) для файловых контрактов
- `references/blueprint-reuse.md` — архивирование и переиспользование blueprint'ов, ADR, итерация на уровне workflow во время выполнения

## Сопутствующий скилл

Этот скилл спроектирован для совместной работы с **[set-skill](https://github.com/tydm2/create-generate-skill)** — мета-скиллом для создания и аудита скиллов. Меню `/skill` в `set-skill` направляет сюда как пункт ④, а `workflow-builder` переиспользует механизмы `set-skill` — feedback-log / usage-log / contract-freeze — для саморазвития subagent'ов.

## Требования

- Агент-хост, способный запускать subagent'ы и читать файлы — нативно в DSH; Codex CLI / Claude Code через адаптер.
- Веб-поиск для community research (опционально; при недоступности корректно деградирует).
