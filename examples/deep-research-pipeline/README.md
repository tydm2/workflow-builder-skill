## ADR (why it's built this way)

- **ADR-01: three specialists, not four** — research, writing, and review are the three stage boundaries with distinct skill sets; a fourth "editor" would overlap the reviewer's QA duty.
- **ADR-02: researcher is single-expert, writer is a panel** — research is process-clear and structured (search → verify → cite), so a single senior expert suffices; writing is subjective and benefits from a 3-role panel (lead + accuracy + style).
- **ADR-03: researcher's knowledge base is refreshable** — search best-practice and source standards change; the base is search-first with a "recent updates" section.

## How to run

1. Say `research <topic>` — the planner clarifies scope and writes `brief-NN.md`.
2. The planner dispatches the researcher (self-contained prompt per `prompt-craft.md`).
3. Say `synthesize` to start the writer on the confirmed brief.
4. Say `review` to run the reviewer's QA.
5. The planner merges into `outputs/final/report-NN.md`.
